# Fixtures

Fixture logbooks used by tests across every layer. Each fixture is a complete
logbook folder in the layout described in [data/json/doc.md](../data/json/doc.md)
— a `yemoja.json` plus the data it points at — so that tests exercise the real
format rather than a simplified stand-in.

## Rules

- **Everything here is invented.** No real dives, no real people, no places anyone
  actually dived, no real e-mail addresses, no dive computer serial numbers taken
  from a device. A fixture that looks plausible is fine; a fixture that is real is
  not.
- **Fixtures are read-only to tests.** A test that needs to modify a logbook copies
  it to a temporary location first. Otherwise one test's changes leak into another's
  expectations, and a failing run leaves the repository dirty.
- **One fixture per situation.** Name it for what it exercises, not for its content:
  a fixture demonstrating a conflict is named for the conflict.
- **Small unless size is the point.** A fixture exists to make a test readable. Where
  volume itself is under test — startup cost, a large import — say so in the
  fixture's own note.
- **Hand-written where possible.** A fixture that was generated by the application
  cannot catch the application writing the wrong thing.

## Layout

Each fixture is a directory. What it contains is up to what it tests, but a short
note inside it should say what it is for, so that a failing test leads somewhere.

```
fixtures/
  <fixture-name>/
    yemoja.json
    ... the data it points at
```

## Status

One fixture, `cousteau`, covering every item type and using the supplied libraries.
What it deliberately exercises, and what it leaves out, is in `cousteau/about.md`.

Narrower fixtures are still wanted for the things it cannot show — conflicts, damaged
files, values outside a fixed set. It is a realistic logbook, not a set of edge cases.
